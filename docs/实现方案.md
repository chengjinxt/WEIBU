# 未卜 WEIBU · 实现方案 v0.1（草案·待拍板）

> 日期：2026-10-14　状态：草案，拍板后按 M1 开工

## 0. 一句话定位

中文预测市场**信息聚合站**：聚合 Polymarket / Kalshi 的公开行情，做中文展示、概率走势、异动榜、跨平台比价。
**只做信息层**——不做交易入口、不挂返佣、不做跟单。

## 1. 合规红线（不可谈判）

1. 站内不出现任何"去交易 / 去下注"按钮与外链；
2. 不挂返佣注册链接，不收平台推广费；
3. 每页显著位置声明：数据仅供信息参考，不构成投资建议；预测市场在部分地区被认定为赌博，风险自负；
4. 上线前找律师过一遍站内文案（按小时付费咨询即可）。

## 2. MVP 范围

**做：**

- Polymarket + Kalshi 公开行情采集入库（均为免费公开接口，无需 key）；
- 首页：热门事件 Top、24h 异动榜（涨跌幅 Top10）、分类导航、搜索框；
- 事件详情页：标题（中英对照）、概率走势图、旗下市场列表与实时概率、跨平台同题比价卡、事件信息（时间 / 交易量 / 流动性）；
- 搜索页、分类浏览页；
- 事件标题中文翻译（AI 翻译并打标"AI 翻译"，热门事件人工校对）。

**不做（v0.2+ 候选）：** 登录/订阅、大户地址追踪、市场情绪指数、异动预警推送（TG/邮件）、中文解读专栏。

## 3. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 + 后端一体 | Next.js 14（App Router）+ TypeScript | SEO 是资讯站生命线；前后端同构；Vercel 原生支持 |
| UI | Tailwind CSS + shadcn/ui | 出活快 |
| 图表 | ECharts | 中文文档全，折线/K线够用 |
| 数据库 | Postgres（Supabase 免费档起步） | 时序快照够用，后期可迁 TimescaleDB |
| 采集 | Vercel Cron（每日） + GitHub Actions（每 5 分钟触发 `/api/cron/*`） | 零运维；Vercel 免费档 cron 仅支持每日及更低频率，高频采集用 GitHub Actions 补齐（公开仓库免费、次数无限） |
| 部署 | Vercel Hobby（免费一条龙：托管 + Postgres + cron + 域名 + HTTPS + CDN） | 零运维；全流程见第 12 节发布方案 |
| 翻译 | DeepSeek API | 中文质量好、便宜；Top500 一次性 + 每日增量，月成本预计 < $5 |

备选：若 Vercel Cron 免费额度不够，采集独立部署到 Fly.io / 轻量 VPS。

## 4. 数据源（已验证：公开免费、无需认证）

### Polymarket

- Gamma API：`https://gamma-api.polymarket.com`（只读，无需认证）
  - `GET /events?active=true&closed=false&order=volume_24hr&ascending=false&limit=100` —— 按 24h 交易量取热门事件
  - `GET /events/{slug}` —— 事件详情（含 `markets[]`、`outcomePrices[]`、`volume`、`volume_24hr`、`liquidity`）
  - `GET /public-search?q=xxx` —— 搜索（注意参数是 `q`，`query=` 会 422）
  - 限流：`/events` 500/10s、`/markets` 300/10s、搜索 350/10s —— 采集量下完全够用
- Data API：`https://data-api.polymarket.com` —— `/trades`、`/holders`（大户数据，v0.2 用）

### Kalshi

- Trade API v2：`https://api.elections.kalshi.com/trade-api/v2`（公开行情无需认证）
  - `GET /markets?status=open&limit=200` —— 市场列表
  - `GET /markets/{ticker}` —— 市场详情
  - `GET /markets/{ticker}/candlesticks` —— 历史 K 线（画走势图用）
  - 未认证限流 10 req/s —— 够用

## 5. 系统架构

```
Polymarket Gamma API ─┐
                       ├→ 采集任务(cron) → Postgres → Next.js API Route → 页面(ISR 缓存)
Kalshi Trade API v2 ──┘         ↓
                          翻译任务(每日增量)
```

- 采集频率：事件全量 1 小时/次；Top200 事件 5 分钟/次价格快照；其余 30 分钟/次；
- 快照表只保留 90 天，定时清理；
- 采集层对 API 字段做防御性解析（字段缺失不崩溃、打日志告警）。

## 9. 测试与验收标准

- 采集：连续 72h 运行成功率 > 99%，失败自动重试 + 日志告警；
- 数据延迟：热门事件价格延迟 < 10 分钟（5 分钟采集 + 页面缓存）；
- 前端：Lighthouse 性能 > 85；接口异常 / 无数据时页面降级不白屏；
- 翻译：抽查 50 条，明显错误 < 5%。

## 10. 风险与未知项

1. **API 变更**：两家都无版本化承诺 → 采集层防御性解析（同 StockSentry 扩展库做法）；
2. **Kalshi 对非美国 IP 限制**：待实测（采集跑 Vercel 海外节点，预计无影响）；
3. **Vercel 国内访问速度**：上线后实测，慢则加 Cloudflare 优化或换部署；
4. **中文事件天然少**：Polymarket 以美国政治 / 体育为主 → 中文解读是差异化，但供给依赖 AI + 人工，MVP 先做标题翻译；
5. **成本**：Supabase + Vercel 免费档起步；翻译月 < $5；域名 1 个。

## 12. 发布方案（免费一条龙：Vercel + GitHub Actions，全流程跑通）

### 12.1 平台选定

**Vercel Hobby（免费档）**一条龙包下：代码托管部署、Postgres 数据库、每日 cron、自定义域名、HTTPS 证书、全球 CDN，全部 $0。

免费额度（够 MVP 用）：

- 托管：100GB 带宽/月，函数单次 60 秒超时，`*.vercel.app` 免费二级域名；
- 数据库：Vercel Postgres 免费档 256MB（或 Supabase 免费档 500MB，二选一）；
- Cron：免费档最多 2 个，且**仅支持每日及更低频率**；
- 限制：Hobby 仅限非商用（MVP 个人项目符合）；超额自动停服、不扣费。

**高频采集的解法**：MVP 需要 5 分钟级价格快照，Vercel 免费 cron 做不到 → 用 **GitHub Actions**（公开仓库免费、次数无限）每 5 分钟 curl 触发站内的 `/api/cron/snapshot` 接口，接口用 `CRON_SECRET` 鉴权。这是社区验证过的标准绕法。

备选说明：Cloudflare（Pages + D1 + Workers Cron）免费额度更大，但 Next.js 需转接适配器、摩擦高；Render 免费 Postgres 会过期（陷阱）；Netlify 新版按点数计费不友好。故首选 Vercel。

### 12.2 全流程（按顺序操作）

**第 1 步：代码上 GitHub（用户操作，约 5 分钟）**

1. GitHub 新建空仓库（如 `chengjinxt/weibu`，公开）；
2. 本地仓库推送：

```bash
git remote add origin https://github.com/chengjinxt/weibu.git
git add -A && git commit -m "chore: 初始化 WEIBU 项目"
git push -u origin master
```

**第 2 步：Vercel 一键部署（用户操作，约 10 分钟）**

1. 用 GitHub 账号登录 vercel.com → Add New → Project → Import `chengjinxt/weibu`；
2. Framework Preset 选 Next.js，环境变量先留空，直接 Deploy；
3. 得到 `https://weibu-xxx.vercel.app`，确认能打开。

**第 3 步：挂数据库（约 10 分钟）**

- 方案 A（推荐）：Vercel 项目页 → Storage → Create Database → Postgres，按向导创建，`DATABASE_URL` 自动注入环境变量；
- 方案 B：Supabase 建免费项目，把连接串填进 Vercel → Settings → Environment Variables；
- 跑 migration 建表（`npm run db:migrate` 或 Prisma migrate）。

**第 4 步：配采集 cron（约 20 分钟）**

1. `vercel.json` 配 1 个每日 cron（全量事件同步）：

```json
{ "crons": [{ "path": "/api/cron/sync-events", "schedule": "0 1 * * *" }] }
```

2. 仓库加 workflow `.github/workflows/snapshot.yml`，每 5 分钟触发价格快照：

```yaml
on:
  schedule:
    - cron: "*/5 * * * *"
jobs:
  snapshot:
    runs-on: ubuntu-latest
    steps:
      - run: curl -s -H "Authorization: Bearer ${{ secrets.CRON_SECRET }}" https://你的域名/api/cron/snapshot
```

3. Vercel 环境变量加 `CRON_SECRET`（随机字符串），两个 cron 接口都校验它；GitHub 仓库 Settings → Secrets 做同名配置。

**第 5 步：绑域名（二选一）**

- **MVP 推荐**：直接用 `*.vercel.app`，零成本、零等待；
- 用自有域名（4 个 .si 之一）：Vercel → Settings → Domains → 添加域名 → 按面板提示去 Dynadot DNS 加记录（apex 加 A 记录、`www` 加 CNAME 到 `cname.vercel-dns.com`，以 Vercel 面板显示的值为准）→ Vercel 自动签发 HTTPS 证书。

**第 6 步：上线验证清单**

- [ ] 首页 / 详情页可访问，HTTPS 正常；
- [ ] 每日 cron 跑通，事件正常入库；
- [ ] GitHub Actions 每 5 分钟触发成功，`price_snapshots` 有新数据；
- [ ] 无数据 / 接口异常时页面降级不白屏；
- [ ] Google Search Console 提交 `https://域名/sitemap.xml`。
